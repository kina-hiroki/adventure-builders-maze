# Adventure Builders（集会の裏で冒険仕込む仲間）

ブラウザーで確認： [https://kina-hiroki.github.io/adventure-builders-maze/](https://kina-hiroki.github.io/adventure-builders-maze/)

段ボール迷路「パターン01」を立体で確認する、ブラウザー向けの3Dアプリです。
Vite・TypeScript・Three.jsを使用し、アプリのソースは `games/` にまとめています。

## 主な機能

- 縦7m × 横7m、壁高1.5mの迷路と寸法・区画座標を表示
- 正解ルートを床から75cmの高さにオレンジ色の点線で表示し、STARTからGOALへ点滅して流れるアニメーションを表示。非表示時・タブが非表示の間は停止し、OSの動きを減らす設定では静止表示
- 斜め・真上・真横・正面・右側・背面・左側への視点切り替え
- 回転、拡大率100〜300%、全体表示へのリセット
- 壁を透かして奥の通路や正解ルートを確認する機能
- 左右・背面の壁に、丸・正方形・ひし形の貫通する窓を1m間隔で配置し、窓あり／窓なしを切り替え
- 入口A7の左横に身長130cmの人物を同じ縮尺で表示し、表示・非表示を切り替え
- 正面の壁に、子どもたちの絵を飾る高さ1.5m・幅5mの白い板を配置
- F2上辺に赤✕・G2上辺に青〇、D7上辺の左半分に赤✕・右半分に青〇の透かし壁を配置。「○×クイズを表示」でまとめて切り替え、マウスを合わせる・タップで説明を表示
- D5・D6の中心を南北に通る2mの壁を配置し、左右それぞれ0.5m幅の通路を表示。正解ルートは右側を通る
- B1〜C1に、幅1.5m・長さ2m・中央高さ1mの半円型トンネルを東西方向へ配置。「トンネル」の選択欄で「表示ON」（初期選択）・「表示OFF」・「透かし」を切り替え。壁とは個別に設定可能。マウスを合わせる・タップで寸法と説明を表示
- A1・D1の北側の壁を開口し、本体の外側に幅1m・横4mの抜け道を追加。正解ルートを「両方（トンネル・抜け道）」「すべて（3経路）」「トンネル経由」「抜け道経由」「E3→F3→F2経由」で切り替え
- 元の平面図PDFの参照

設定欄は迷路図の右側に、正解ルート → 正解ルートの経路 → 視点 → 回転 → 拡大率 → 壁の透かし → 外壁の窓 → 人物 → ○×クイズ → トンネル（表示ON・表示OFF・透かし）→ 山越えゾーン（表示ON・表示OFF・透かし）の順で並びます。
画面幅680px以下では迷路図の下に配置します。

座標は左からA〜G、上から1〜7です。基本の49区画のうち、D4・D5・D6を左右、B2・C2・F7を上下、F5・G5を50cm四方の4区画に分けた本体61通行区画に、抜け道の4区画を加えた65通行区画がすべてつながります。循環は7つあります。
D4は中央の縦壁で `D4W`（西側）と `D4E`（東側）に分けます。D4WはC4とD5Wをつなぎますが、上辺の延長壁によりD3へは進めません。正解ルートはE4 → D4E → D3と進み、東側50cm幅の中央（x=3.75m）を通ります。縦壁は既存のD5・D6中央壁とつながり、上から3〜6mの計3mになります。
D5・D6の西側は `D5W`・`D6W`、東側は `D5E`・`D6E` と表します。中央壁はD5の上辺からD6の下辺まで伸び、西側はD5WからD4Wへ抜け、右側はD5EからE5へ進めます。
B2・C2の北側は `B2N`・`C2N`、南側は `B2S`・`C2S` と表します。正解ルートはC2SからB2Sへ、移動した壁の南側0.5m幅の通路を通ります。A2からA1へ上がり、B1・C1付近の幅1.5mの通路中央を通ってD1からD2へ進みます。横方向の線は上側の外壁（z=0m）と移動した壁（z=1.5m）の中間（z=0.75m）にそろえます。
F5・G5はそれぞれ左上 `NW`、右上 `NE`、左下 `SW`、右下 `SE` の50cm四方に分けます。✕側はF4 → F5NW → F5SW → F5SE → G5SWと進み、G5左下（中心x=6.25m、z=4.75m）で行き止まりになります。〇側の正解ルートはF4 → F5NE → G5NW → G5NE → G5SE → G6と進み、上側と右側の幅50cmの通路を通ります。
F7の上半分は `F7N`、下半分は `F7S` と表します。正解ルートはE7からF7Nの中央（z=6.25m）を通ってG7へ進みます。F7SはE7側から入る行き止まりです。
トンネル経由の正解ルートはC7・B1・C1を順に経由する指定と通行区画の隣接関係から計算し、幅0.5mの通路と、B1・C1付近の幅1.5mの通路の中央を通る直角の線で描画します。
両経路ともC7を経由して、既存のクイズの〇側を進む正解ルートを保ちます。E5からE4へは、E5上辺の右半分の開口中央（x=4.75m）を通します。
抜け道経由ではA1 → 北側の抜け道（4区画）→ D1 → D2と進み、B1・C1を通りません。設定欄の「正解ルートの経路」で切り替えます。初期選択は「両方（トンネル・抜け道）」で、正解ルートの表示をオンにすると両方を同時に表示します。共通区間は1本の点線で描き、分岐から合流までの抜け道を追加表示します。経路を変えてもルートの表示・非表示と視点は保持します。「全体表示に戻す」でも経路の選択は保持します。
E3→F3→F2経由はC7を通った後、D3 → E3 → F3 → F2 → F1と進んで既存ルートに合流します。F2→F1は既存の赤✕を裏側から通過する向きです。D3–E3間は上側50cm、E3–F3間は下側50cmの開口中央を通ります。選択欄の「E3→F3→F2経由」で個別表示、「すべて（3経路）」で既存の2経路と同時表示できます。D4東側からD3へはx=3.75mのまま北へ進み、z=2.25mで右へ曲がってE3の開口中央へつなぎます。D3中心への余分な折り返しは入れません。同時表示では実際の描画線からD3〜F1の分岐区間だけを切り出し、共通部分の点線を重ねず、分岐位置もそろえます。初期選択は従来どおり「両方（トンネル・抜け道）」です。
抜け道は本体北側の別の床面として表示し、幅1m・横4mの寸法を併記します。配置データは `externalPassages`、追加の経路は `alternativeSolutions` に分離し、トンネルの表示設定は通行可否に影響しません。
壁厚は表示用に0.045mとしています。7mの寸法は元図のグリッドを基準にしています。
外周窓は3D案の追加仕様です。丸・正方形・ひし形をランダムに混ぜた固定配置とし、視点変更や再読み込みで配置が変わらないようにしています。
窓は壁厚を貫通する穴で、向こう側の通路が見えます。
正面は入口A7・出口G7がある側です。「外壁の窓を表示」は初期状態でオンです。オフにすると左右・背面も穴のない壁に切り替わります。

人物は足裏から頭頂まで1.30mで、入口の通路をふさがない外側に配置します。図中に「130 cm」を表示します。「人物を表示」は初期状態でオンです。

白い板は正面の壁の外側に密着させ、床から壁の上端までの高さにしています。板の表面に1m間隔の黒い縦の点線を4本引き、幅1mずつの5区間に分けています。板厚は表示用に2cmとしています。「壁を透かす」に合わせて板と点線も透けます。吹き出しは寸法と「子供たちに絵を書いてもらった段ボールを配置」の説明を表示します。

元図は [pattern01.pdf](games/public/reference/pattern01.pdf) です。
このPDFは元資料として保持しており、D5・D6中央の壁追加、D7のクイズ、B2・C2上辺の壁の50cm移動と両端の縦壁の切り詰め、F5・F7の壁追加、A1・D1の上辺の開口と北側の抜け道追加、D3–E3間の縦壁撤去、C4右辺のD4中央への移動と上辺の50cm延長、D5上辺左50cmの回転とE5上辺左50cmの壁追加、F5の行き止まりをG5左下まで延長する壁変更、E3左下・F3左上の縦50cm壁追加はアプリ側の変更です。
壁配置・正解ルートと元図のSHA-256は [pattern01.ts](games/src/maze/pattern01.ts) に保持しています。

## ローカルで起動する

プロジェクト直下から実行します。

```powershell
Set-Location -LiteralPath '.\games'
npm.cmd ci
npm.cmd run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

[http://127.0.0.1:5173/adventure-builders-maze/](http://127.0.0.1:5173/adventure-builders-maze/) をブラウザーで開きます。
`npm.cmd ci` は初回取得時や依存関係の入れ直し時に実行します。導入済みで変更がなければ再実行は不要です。
以降のnpmコマンドも `games/` で実行します。

ポートが使用中なら `--port 5174` などへ変更してください。サーバーは `Ctrl+C` で停止します。

## 操作方法

| 操作 | 方法 |
|---|---|
| 回転 | 迷路をドラッグ、または回転スライダー |
| 拡大・縮小 | マウスホイール、または拡大率スライダー |
| 平行移動 | 右ドラッグ。迷路にフォーカスした状態では矢印キーも使用可能 |
| タッチ操作 | 1本指で回転、2本指で拡大・移動 |
| 白い板の説明 | 板にマウスを合わせる、またはタップ。板以外をタップ・視点操作で閉じる |
| ○×クイズの説明 | 赤✕・青〇の透かし壁にマウスを合わせる、またはタップ。表示切替は初期状態でオン |
| トンネルの表示 | 「トンネル」の3択で切り替え。「表示ON」（初期選択）で通常表示、「表示OFF」で非表示、「透かし」で天井と側壁を半透明表示。「壁を透かす」とは個別に設定可能。非表示中は寸法と説明も表示しない |
| キーボードで部品の説明 | 迷路にフォーカスしてEnterで白い板・赤✕・青〇・トンネル・山越えゾーンの説明を順に切り替え、Escで閉じる。非表示のクイズ・トンネル・山越えゾーンは対象外 |
| 初期の視点へ戻す | 「全体表示に戻す」ボタン |

全体表示へ戻しても、正解ルート・壁とトンネルと山越えゾーンの透かし・窓・人物・○×クイズ・トンネル・山越えゾーンの表示状態は保持します。トンネルと山越えゾーンはそれぞれ「表示ON」「表示OFF」「透かし」の3択で、全体表示へ戻しても選択を保持します。
壁に隠れた正解ルートは、透かしか真上表示で確認できます。

## JavaScriptの分割と読み込み

画面を組み立てた後、3D処理を動的importで読み込みます。迷路は自動表示します。
読み込み中は「3Dを読み込み中」を表示し、3Dの設定操作を無効にします。
ファイル取得に失敗した場合は通信環境の確認、3D初期化に失敗した場合はWebGL 2対応ブラウザーの案内を表示し、「再読み込み」ボタンを用意しています。
画面更新・終了後に遅れて読み込みが完了しても、終了した画面を作り直しません。

2026年10月26日のローカルビルドで確認した構成です。容量は10進kB、gzipは同じNode.jsのgzipSyncで比較しています。実際のHTTP転送量ではありません。

| 配信JS | 内容 | 容量 | gzip容量 |
|---|---|---:|---:|
| index-[hash].js | 画面・設定・迷路データと解析・起動処理 | 13.93 kB | 5.96 kB |
| maze-view-[hash].js | 迷路の3D処理・人物・板・窓・吹き出し | 12.59 kB | 5.66 kB |
| three-[hash].js | Three.jsとOrbitControls | 594.79 kB | 147.85 kB |
| 合計 |  | 621.31 kB | 159.47 kB |

分割前は1本で617.98 kB、gzip 157.59 kBでした。読み込み・失敗処理の追加により合計容量は少し増えています。
画面側の変更だけでThree.jsのファイル名が変わらないことを再ビルドで確認しています。ブラウザーがキャッシュを再利用しやすくするための分割です。
初回は3D表示に必要な全ファイルを取得します。表示速度の改善率や10回の通信量・表示時間は未計測です。
Three.js側の500kB超の容量警告は継続しています。

分割設定はVite 8の `build.rolldownOptions.output.codeSplitting` を使用しています。
[loadView.ts](games/src/loadView.ts) の非同期読み込み・失敗の区別・終了後の作成防止・リソースの解放は単体テストで確認します。
開発サーバーと本番プレビューで初期画面、全視点、回転・拡大、各表示設定、板の吹き出し、画面サイズ変更とファイル取得失敗からの復旧を確認しています。

## GitHub Pages向けのパス設定

[vite.config.ts](games/vite.config.ts) の `base` を `/adventure-builders-maze/` に設定しています。
開発サーバー・ビルド後のプレビューでも、このパスを使用します。
この設定を追加する前から開発サーバーを起動していた場合は、再起動して設定を読み込み直してください。
ホームと参照PDFへのリンクは `import.meta.env.BASE_URL` を使用し、公開先のパスに合わせます。
設定方法は [Viteの公開パスの説明](https://vite.dev/guide/build.html#public-base-path) を参照してください。

GitHub Pagesの公開設定が完了した後のURLは `https://kina-hiroki.github.io/adventure-builders-maze/` です。

## 自動公開ワークフロー

[deploy.yml](.github/workflows/deploy.yml) に、GitHub Actionsの自動公開処理を定義しています。
`main` 向けのプルリクエスト、`main` へのプッシュ、またはActions画面からの手動操作で実行します。

処理の順番は次のとおりです。

1. Ubuntu上にNode.js 24を用意し、`games/package-lock.json` に基づいてnpmのキャッシュを使用
2. `games/` で `npm ci` を実行して依存ライブラリを導入
3. `npm audit --audit-level=high` で開発用・任意の依存関係も監査し、高・重大の脆弱性、または照合失敗で処理を停止
4. `npm test` で単体テストを実行
5. `npm run build` で型チェックとビルドを実行
6. プルリクエスト以外では `games/dist/` を公開用の成果物としてアップロード
7. 公開する実行では、`build` 成功後に `deploy` でGitHub Pagesへ公開

プルリクエストでは監査・テスト・ビルドまでを実行し、成果物のアップロードと公開は行いません。
ローカルでも `games/` で `npm audit --audit-level=high` を実行できます。依存関係の自動修正は行いません。

手動実行時に「GitHub Pagesへ公開する」のチェックを外すと、公開せずにテスト・ビルドと成果物の作成だけを確認できます。
手動で公開する場合も、ブランチは `main` を選択します。
使用するGitHub公式ActionsはコミットSHAで固定しています。

### 初回公開の実施手順

1. リポジトリの **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選択
2. **Actions → Deploy to GitHub Pages → Run workflow** を開く
3. ブランチを `main` にし、「GitHub Pagesへ公開する」にチェックを入れて **Run workflow** を実行
4. `build` と `deploy` が成功したことを確認
5. 表示された公開URLで、迷路・各設定・ホームへの移動・元図PDFを確認

以後は `main` へのプッシュ時に自動で更新します。
初回公開の設定方法は [GitHubの公式手順](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site#publishing-with-a-custom-github-actions-workflow) も参照してください。

迷路のデータ・解析処理とThree.jsによる描画処理を分けています。
経路座標は解析時の計算結果を描画へ渡します。同寸法の箱・平面と同じ色・記号のクイズ画像は表示内で共有します。
描画とホバー判定は1フレーム内の要求をまとめます。部品を後から追加・削除した場合は、説明表示の `refresh()` で交差判定対象を更新します。
初期化途中の失敗でも、通常終了と同じ後始末を実行します。共有資源は一度だけ解放し、Three.jsが共有するSpriteの形状は解放対象に含めません。
`node_modules/` と `dist/` は自動生成されるためGit管理の対象外です。

## 山越えゾーンの単体サンプル

ローカル起動後、[山越えゾーンのサンプル](http://127.0.0.1:5173/adventure-builders-maze/mountain.html) を開きます。
高さ50cm・幅1.0m・長さ2.0mで、両端は床面、中央が頂点の対称な山型です。

## 迷路内の山越えゾーン

A5〜A6に南北方向の長さ2m、F6に東西方向の長さ1mの山型パーツを配置しています。
どちらも幅1m・高さ50cmで、両端が床面、中央が頂点です。
設定欄のトンネル設定の下に「山越えゾーン」の選択欄を配置しています。「表示ON」（初期選択）で通常表示、「表示OFF」で非表示、「透かし」で半透明表示に切り替えます。
山越えゾーンの選択は壁・トンネルから独立し、全体表示に戻しても保持します。
マウスを合わせる・タップ、または迷路上でEnterキーを押すと、寸法と説明を表示できます。非表示中は吹き出しの対象外です。
壁配置・正解ルート・壁用段ボールの枚数は変更せず、山越えパーツの材料は壁用段ボールに含めません。
配置データは `games/src/maze/pattern01.ts`、描画と透かし処理は `games/src/three/createMazeMountains.ts` で管理します。
