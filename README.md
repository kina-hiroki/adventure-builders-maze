# Adventure Builders（集会の裏で冒険仕込む仲間）

段ボール迷路「パターン01」を立体で確認する、ブラウザー向けの3Dアプリです。
Vite・TypeScript・Three.jsを使用し、アプリのソースは `games/` にまとめています。

## 主な機能

- 縦7m × 横7m、壁高1.5mの迷路と寸法・区画座標を表示
- 正解ルートを床から75cmの高さにオレンジ色の点線で表示し、STARTからGOALへ点滅して流れるアニメーションを表示。非表示時・タブが非表示の間は停止し、OSの動きを減らす設定では静止表示
- 斜め・真上・真横・正面・右側・背面・左側への視点切り替え
- 回転、拡大率100〜300%、全体表示へのリセット
- 壁の透かし、壁に1m間隔の縦の点線を表示する機能
- 左右・背面の壁に、丸・正方形・ひし形の貫通する窓を1m間隔で配置し、窓あり／窓なしを切り替え
- 入口A7の左横に身長130cmの人物を同じ縮尺で表示し、表示・非表示を切り替え
- 正面の壁に、子どもたちの絵を飾る高さ1.5m・幅5mの白い板を配置
- F2上辺に赤✕・G2上辺に青〇、D7上辺の左半分に赤✕・右半分に青〇の透かし壁を配置。「○×クイズを表示」でまとめて切り替え、マウスを合わせる・タップで説明を表示
- D5・D6の中心を南北に通る2mの壁を配置し、左右それぞれ0.5m幅の通路を表示。正解ルートは右側を通る
- 元の平面図PDFの参照

設定欄は迷路図の右側に、正解ルート → 視点 → 回転 → 拡大率 → 透かし → 縦の点線 → 外壁の窓 → 人物 → ○×クイズの順で並びます。
画面幅680px以下では迷路図の下に配置します。

## 迷路の仕様

| 項目 | 内容 |
|---|---|
| 外寸・区画 | 7m × 7m、7行 × 7列、1区画1m |
| 壁の高さ | 1.5m |
| 壁の区間数 | 外周26区間 ＋ 内部38区間 ＝ 64区間 |
| 壁用段ボール | 高さ1.5mで幅1mを62枚、幅0.5mを2枚の計64枚。壁の総延長は63m。クイズの透かし壁・正面の白い板は別扱い |
| 追加した壁 | F2–G2間、F3–G3間、D5中央、D6中央。中央壁はx=3.5m、上から4〜6mの南北方向に連続する2m |
| 移動した壁 | B2・C2の上辺にあった横2mの壁を下へ50cm移動。x=1〜3m、上から1.5mの位置。両端（x=1m・3m）の縦壁は上へ突き出す50cmを削除し、上から1.5〜2mの範囲だけ残す |
| D7のクイズ | 上辺の左0.5mは赤✕で行き止まり側、右0.5mは青〇で正解側。既存のクイズと同じ高さ1.5mの透かし壁 |
| 入口・出口 | 入口A7、出口G7。どちらも下辺に開口 |
| 外周の窓 | 左右・背面の21区間に1つずつ、1m間隔。正面は窓なし |
| 窓の寸法 | 最大幅・高さ40cm、床から中心まで90cm |
| 正面の白い板 | 高さ1.5m × 幅5m。B7〜F7の外壁に取り付け、入口A7・出口G7を空ける |
| 正解ルート | 45通行区画、曲がり角31回、分岐9か所。D7の右〇 → D6東側 → D5東側 → E5へ進む |

座標は左からA〜G、上から1〜7です。基本の49区画のうち、D5・D6を左右、B2・C2を上下に分けた53通行区画がすべてつながります。上側の縦壁の切り詰めにより、循環は3つあります。
D5・D6の西側は `D5W`・`D6W`、東側は `D5E`・`D6E` と表します。中央壁はD5の上辺からD6の下辺まで伸び、西側はD5Wで行き止まりになります。
B2・C2の北側は `B2N`・`C2N`、南側は `B2S`・`C2S` と表します。正解ルートはC2SからB2Sへ、移動した壁の南側0.5m幅の通路を通ります。A2からA1へ上がり、B1・C1付近の幅1.5mの通路中央を通ってD1からD2へ進みます。横方向の線は上側の外壁（z=0m）と移動した壁（z=1.5m）の中間（z=0.75m）にそろえます。
正解ルートはB1・C1を順に経由する指定と通行区画の隣接関係から計算し、幅0.5mの通路と、B1・C1付近の幅1.5mの通路の中央を通る直角の線で描画します。
壁厚は表示用に0.045mとしています。7mの寸法は元図のグリッドを基準にしています。
外周窓は3D案の追加仕様です。丸・正方形・ひし形をランダムに混ぜた固定配置とし、視点変更や再読み込みで配置が変わらないようにしています。
窓は壁厚を貫通する穴で、向こう側の通路が見えます。
正面は入口A7・出口G7がある側です。「外壁の窓を表示」は初期状態でオンです。オフにすると左右・背面も穴のない壁に切り替わります。

人物は足裏から頭頂まで1.30mで、入口の通路をふさがない外側に配置します。図中に「130 cm」を表示します。「人物を表示」は初期状態でオンです。

白い板は正面の壁の外側に密着させ、床から壁の上端までの高さにしています。板の表面に1m間隔の黒い縦の点線を4本引き、幅1mずつの5区間に分けています。板厚は表示用に2cmとしています。「壁を透かす」に合わせて板と点線も透けます。吹き出しは寸法と「子供たちに絵を書いてもらった段ボールを配置」の説明を表示します。

元図は [pattern01.pdf](games/public/reference/pattern01.pdf) です。
このPDFは元資料として保持しており、D5・D6中央の壁追加、D7のクイズ、B2・C2上辺の壁の50cm移動と両端の縦壁の切り詰めはアプリ側の変更です。
壁配置・正解ルートと元図のSHA-256は [pattern01.ts](games/src/maze/pattern01.ts) に保持しています。

## 必要な環境

- Node.js 24 LTS系とnpm
- WebGL 2が利用できるブラウザー
- 以下のコマンド例はWindowsのPowerShell用

## ローカルで起動する

プロジェクト直下から実行します。

```powershell
Set-Location -LiteralPath '.\games'
npm.cmd ci
npm.cmd run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

[http://127.0.0.1:5173/adventure-builders-maze/](http://127.0.0.1:5173/adventure-builders-maze/) をブラウザーで開きます。
`npm.cmd ci` は初回取得時や依存関係の入れ直し時に実行します。導入済みで変更がなければ再実行は不要です。
以降のnpmコマンドも `games/` で実行します。

ポートが使用中なら `--port 5174` などへ変更してください。サーバーは `Ctrl+C` で停止します。

## 操作方法

| 操作 | 方法 |
|---|---|
| 回転 | 迷路をドラッグ、または回転スライダー |
| 拡大・縮小 | マウスホイール、または拡大率スライダー |
| 平行移動 | 右ドラッグ。迷路にフォーカスした状態では矢印キーも使用可能 |
| タッチ操作 | 1本指で回転、2本指で拡大・移動 |
| 白い板の説明 | 板にマウスを合わせる、またはタップ。板以外をタップ・視点操作で閉じる |
| ○×クイズの説明 | 赤✕・青〇の透かし壁にマウスを合わせる、またはタップ。表示切替は初期状態でオン |
| キーボードで部品の説明 | 迷路にフォーカスしてEnterで白い板・赤✕・青〇の説明を順に切り替え、Escで閉じる。非表示のクイズは対象外 |
| 初期の視点へ戻す | 「全体表示に戻す」ボタン |

全体表示へ戻しても、正解ルート・透かし・縦の点線・窓・人物・○×クイズの表示状態は保持します。
壁に隠れた正解ルートは、透かしか真上表示で確認できます。

## テスト・ビルド

```powershell
npm.cmd test
npm.cmd run build
```

単体テストで壁数、追加壁、全区画の接続と正解ルート、B1・C1付近の通路中央を通る直線と不正な通過位置・経由区画の検出、入口・出口の開口、不正データの検出を確認します。
中央壁の位置・長さと段ボール64枚、左右の通路幅、左側の行き止まり、右〇を通る正解ルート、描画線分が壁を横切らないこと、B2・C2の壁の50cm移動と南側の通路、両端の上側50cmの除去と下側50cmの保持、すべての変更を戻した元の配置も確認します。
外周窓の配置・再現性と、3種類の穴が実際に貫通し、断面に厚みがあることも確認します。
人物の実寸と、入口をふさがない配置も確認します。
正解ルートのアニメーションは、進行方向・表示切り替え・動きを減らす設定・バックグラウンド停止・終了時の解放を確認します。
吹き出しは、クイズ壁・記号へのホバー、非表示や遮蔽時の判定、白い板の説明、タップとドラッグ、キーボード操作と終了時のイベント解除を確認します。
ビルドはTypeScriptの型チェック後にViteで実行し、`games/dist/` に出力します。

ビルド結果をブラウザーで確認する場合は、次を実行します。

```powershell
npm.cmd run preview -- --host 127.0.0.1 --port 4173 --strictPort
```

[http://127.0.0.1:4173/adventure-builders-maze/](http://127.0.0.1:4173/adventure-builders-maze/) を開きます。プレビューはローカル確認用です。

## JavaScriptの分割と読み込み

画面を組み立てた後、3D処理を動的importで読み込みます。迷路は自動表示します。
読み込み中は「3Dを読み込み中」を表示し、3Dの設定操作を無効にします。
ファイル取得に失敗した場合は通信環境の確認、3D初期化に失敗した場合はWebGL 2対応ブラウザーの案内を表示し、「再読み込み」ボタンを用意しています。
画面更新・終了後に遅れて読み込みが完了しても、終了した画面を作り直しません。

2026年10月26日のローカルビルドで確認した構成です。容量は10進kB、gzipは同じNode.jsのgzipSyncで比較しています。実際のHTTP転送量ではありません。

| 配信JS | 内容 | 容量 | gzip容量 |
|---|---|---:|---:|
| index-[hash].js | 画面・設定・迷路データと解析・起動処理 | 13.93 kB | 5.96 kB |
| maze-view-[hash].js | 迷路の3D処理・人物・板・窓・吹き出し | 12.59 kB | 5.66 kB |
| three-[hash].js | Three.jsとOrbitControls | 594.79 kB | 147.85 kB |
| 合計 |  | 621.31 kB | 159.47 kB |

分割前は1本で617.98 kB、gzip 157.59 kBでした。読み込み・失敗処理の追加により合計容量は少し増えています。
画面側の変更だけでThree.jsのファイル名が変わらないことを再ビルドで確認しています。ブラウザーがキャッシュを再利用しやすくするための分割です。
初回は3D表示に必要な全ファイルを取得します。表示速度の改善率や10回の通信量・表示時間は未計測です。
Three.js側の500kB超の容量警告は継続しています。

分割設定はVite 8の `build.rolldownOptions.output.codeSplitting` を使用しています。
[loadView.ts](games/src/loadView.ts) の非同期読み込み・失敗の区別・終了後の作成防止・リソースの解放は単体テストで確認します。
開発サーバーと本番プレビューで初期画面、全視点、回転・拡大、各表示設定、板の吹き出し、画面サイズ変更とファイル取得失敗からの復旧を確認しています。

## GitHub Pages向けのパス設定

## 自動公開ワークフロー

[deploy.yml](.github/workflows/deploy.yml) に、GitHub Actionsの自動公開処理を定義しています。
`main` へのプッシュ、またはActions画面からの手動操作で実行します。

処理の順番は次のとおりです。

1. Ubuntu上にNode.js 24を用意し、`games/package-lock.json` に基づいてnpmのキャッシュを使用
2. `games/` で `npm ci` を実行して依存ライブラリを導入
3. `npm test` で単体テストを実行
4. `npm run build` で型チェックとビルドを実行
5. `games/dist/` を公開用の成果物としてアップロード
6. 公開する実行では、`build` 成功後に `deploy` でGitHub Pagesへ公開

手動実行時に「GitHub Pagesへ公開する」のチェックを外すと、公開せずにテスト・ビルドと成果物の作成だけを確認できます。
手動で公開する場合も、ブランチは `main` を選択します。
使用するGitHub公式ActionsはコミットSHAで固定しています。

### 初回公開の実施手順

1. リポジトリの **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選択
2. **Actions → Deploy to GitHub Pages → Run workflow** を開く
3. ブランチを `main` にし、「GitHub Pagesへ公開する」にチェックを入れて **Run workflow** を実行
4. `build` と `deploy` が成功したことを確認
5. 表示された公開URLで、迷路・各設定・ホームへの移動・元図PDFを確認

以後は `main` へのプッシュ時に自動で更新します。
初回公開の設定方法は [GitHubの公式手順](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site#publishing-with-a-custom-github-actions-workflow) も参照してください。
